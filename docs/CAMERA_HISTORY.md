# 相机构图历史与本地恢复

2026-10-26：已接入云端生成式流程的本地历史。仅保存成功构图，不保存离线 GLB，不自动恢复收费请求。真机交互及摄影效果由用户验收。

## 交互

- 相机左上两条横线打开 `ModalNavigationDrawer`，`ModalDrawerSheet` 从左侧覆盖相机，宽度固定为当前窗口的 3/4，右侧留 1/4 遮罩区域（不再限制最大 360dp）。打开收起键盘；遮罩、系统返回、向左滑动关闭。关闭时禁用边缘滑动打开，避免抢占相机手势；打开和关闭不会改变取景尺寸或重新绑定相机。
- 抽屉展开时由 App `NavigationSystemBars` 常驻显示顶部时间、电量等白色状态栏信息，同时显示底部系统导航栏，与首页／我的一样展示上下系统栏；关闭抽屉时一起恢复隐藏。前台／焦点恢复沿用当前抽屉状态，离开相机恢复普通页面策略。仅改变系统栏可见性，不重设相机窗口刘海策略或取景尺寸。
- 抽屉标题取消额外 20dp 上下留白，和相机顶部栏共用安全区后 48dp 行高，标题及右侧模型设置／拍照设置按钮垂直居中。设置按钮沿用原图标、旋转及操作门控，点击直接覆盖原设置弹窗，保留抽屉展开状态；返回先关闭设置。拍照设置中的模式切换使用独立门控，抽屉覆盖相机时仍禁止拍摄和变焦。
- 原返回图标为白色 X，位于相机右上，保留原退出与照片保存门控。两个设置入口仅在抽屉中显示；中间 AI 入口相对整行父组件居中，按两侧最大按钮占位限制宽度以避免重叠。
- 历史分为置顶和最近，同一条只出现一次。置顶按置顶时间倒序，最近按最后成功时间倒序；仅查看不更新排序。长按可置顶、取消置顶、删除，删除需确认。
- 缩略图固定为该流程第一张成功构图，标题和模型副标题随最新一次成功生成更新。空用户文案使用 AI 输入框默认文案，标题和副标题均单行省略。
- 生图、扫描、照片保存、历史保存或恢复期间可以浏览历史和置顶，不能切换流程或删除。抽屉覆盖期间禁用相机拍摄入口。

- 相机顶部由 `rememberCameraSafeInsets` 在进入当前布局时锁定安全高度（状态栏／刘海、窗口 Insets 与设备资源共同兜底）；抽屉及系统栏显隐不重新计算。只有布局方向或显示密度改变才重算，不以可能受系统栏影响的 `screenHeightDp` 为缓存键。隐藏状态栏也不侵占该区域。相机底部位置固定：时间线固定预留 24dp，不再读取会随系统栏显隐变化的 `mandatorySystemGestures` 或导航栏高度来移动相机 UI。系统横条出现、消失或抽屉开关不移动快门、操作区和时间线，不改预览尺寸。
- 时间线仍固定 24dp 容器、20dp 节点、16dp 图标，独立叠加底部，无动态缩放或偏移。抽屉背景铺满窗口高度，自己的内部内容按可见系统栏避让，不传递给底层相机；拍摄页底部导航栏透明、关闭对比度遮罩及分隔线，系统横条直接叠在抽屉背景上，无独立黑色底条。

## 模块与持久化

```text
VlmIntent → VlmCameraViewModel（MVI）
  → CameraCompositionHistory（feature：DTO 转换、图片文件）
  → CameraHistoryRepository（core-data：数据库接口）
  → CameraHistoryDao / CameraHistoryDatabase（core-database：Room）
```

`camera-history.db` 与原 MyModel `AppDatabase` 完全独立。`camera_history_sessions` 保存流程摘要、置顶、选择、风格历史和现场快照；`camera_history_results` 按流程关联成功候选，保存完成时间和专用 JSON DTO。列表查询只读取摘要，不加载所有提示词或扫描快照。Schema 位于 `core-database/schemas/com.framer.sense.core.database.CameraHistoryDatabase/1.json`。

每张候选记录用户原文、实际发送的完整提示词、模板版本、模型 ID、人物偏好、输出参数、完成顺序、说明及完整图和透明人像路径。请求记录不包含 API Key、请求头或输入照片的 Base64。`HistoryScene` 显式保存照片方向、来源绑定等运行时 `Transient` 字段；扫描帧、原现场图和模型输入图一并保存。恢复时不复用旧 IMU 基准作为实时姿态。

图片不进数据库：扫描及冻结缓存复制至 `filesDir/camera-history/{流程ID}/scenes/`，缩略图保存在该流程目录。生成的完整图和透明图复用 `filesDir/generated-references/{候选ID}/`。数据库仅保存经私有目录校验的相对路径。

文件先以 `.pending` 写入、同步、重命名，再提交 Room 事务。首张完整图就绪才创建历史行，后续成功追加；没有可用透明人像的完整预览仍保存，应用按钮继续受 `canApply` 限制。重复回调不重复插入，较早结果的本地补存不回退最新标题、模型和最近时间。首次缩略图、置顶及已有选择不会被追加覆盖。

写任务通过应用级串行队列执行，页面销毁不会截断已经入队的保存；清理源缓存前等待 `flush()`。本地保存失败保留生成结果，在抽屉显示“重试本地保存”，不重新请求模型。重试缓冲存在当前 ViewModel 内，进程被杀后未完成的本地重试缓冲不会自动恢复。

删除先移除数据库流程及关联结果，再清理对应现场目录和生成资源。若删除当前流程，清空相机参考并回到实时预览。历史数据库、现场目录及生成资源目录均排除 Android 云备份；不实现云端同步。

## 恢复与继续生成

- 点击历史后关闭抽屉，验证必需文件，恢复至构图选择阶段，展示全部成功构图，选中上次选择；选项不存在则选最近成功项。关键文件缺失提示无法完整恢复，条目仍保留供删除，不补发收费请求。
- 恢复原流程 ID、原现场及扫描界面、来源绑定、方向和原画幅。历史画幅只覆盖当前流程，比例入口锁定，不写全局偏好；重新开始时恢复全局比例。
- 清空应用参考、背景对齐、拍摄完成状态和相机任务令牌。点击应用后重新进行原现场对齐，不恢复旧 AR 会话；AI 人像仍只使用普通相机。
- 输入框恢复最近成功文案。后续生成用当前模型、当前人物偏好与最新模板，追加回原历史；历史提示词只作记录，不直接重放。手动更换模型设置不清空已恢复历史。
- 风格组合同时保存文本快照和由两项文本组成的稳定键。后续随机排除已提交组合，包含失败的尝试，不依赖本地列表下标；调整池的顺序不破坏去重。失败不更新标题、模型副标题或最近时间。
- 离线可查看和应用已有透明人像；继续生成时提示手动切换云端，不自动换品牌或模式。恢复本身不调用任何模型。
- 流程 ID 与候选 ID、生成 epoch、请求 token 分开；恢复校验 token，生成回传校验 epoch 和候选身份，保存快照校验所属候选，避免跨流程串写。
