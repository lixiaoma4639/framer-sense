# AR 人像尺度校准

> 当前主路径为 [VLM 摄影布局优先](CAMERA_VLM_PHOTOGRAPHY_V3.md)。下文自动景别裁切及距离先验仅保留在兼容/降级路径；新协议不允许 AR 改写模型裁切，有效模型头脚目标不被距离先验覆盖。

软件接入已完成；自动化测试代码已补充，尚未运行构建/测试。AR 真机比例验收待用户完成。此批不修改动作素材，不代表摄影动作或商业质量验收通过。

## 使用方式

拍照设置选择角色并设置身高：女性 165 cm、男性 175 cm、儿童 120 cm。成人范围 120～220 cm，儿童 60～180 cm，按角色保存。修改只影响下一次生成，现有方案保留原身高。

当前按用户确认改为“实测优先、估算也显示”：普通相机和 AR 未取得可靠地面时，三张卡片仍绘制人像并标注“估算比例”。估算依次参考环境深度、AR 米制特征点、VLM 建议人物区域及原模型布局；都不可用时根据身高、景别、假定距离和假定焦距计算屏幕比例。无需额外模型调用。估算不等于真实测量，不恢复隐含的固定 23%/46% 人体占比。

2026-10-12 成功率修正：稳定 AR 平面自身提供米制站位，深度图不再是计算身高投影的必要条件。自动站位仍要求至少三次连续稳定观察、有效平面面积至少 0.25 平方米，相机距地面高度自动要求 0.8～2.4 米；面积从 1 平方米降低，避免刚识别出的有效地面被全部排除。没有深度时仍以真实地面、固定身高和相机投影求解，不恢复默认人体占比。平面语义仍不能证明实际地面或可站立安全性。

深度作为增强证据与前景遮挡约束，不强制人物与远景同深度，不再要求人物站位附近恰好有三个原始深度像素。背景深度用于站位择优，人物在近处、风景在远处可以是合法摄影关系。每个采样格选择置信度最高的有效像素，最多约 32×24 点，置信度仍要求至少 160/255；接受 ARCore 提供的重投影深度，不再把深度时间戳较旧直接当作失效。深度/置信度图尺寸和时间戳仍须匹配。接口依据：[ARCore 原始深度说明](https://developers.google.com/ar/develop/java/depth/raw-depth)。

无固定 88% 画面高度或固定人体占比目标。模型有建议人物区域时使用其下缘，否则搜索实测地面网格。环境景别在合法候选中偏向远处，全身/半身/特写偏向较近的有效站位；具体大小仍由米制站位决定。半身/特写不再要求脚先出现在原图内；头部需在有效取景中，最终裁切须满足景别和保护背景，无法同时满足仍明确提示调整机位，不伪造成功。

每张卡片区分“已校准”和“估算比例”。实测求解失败、尺度元数据缺失或空间失效时重新估算屏幕参考，不返回透明空人像。AR 相机和资源单位可用时，估算站位可建立普通世界锚点，不要求 Plane；旧会话锚点不得复用。背景确认后，锚点尚未放置或失跟时保留同参数屏幕人像。估算不画实测接触阴影、不宣称可站立性或真实尺寸已确认。普通 CameraX 不宣称能测量真实比例。

应用方案并找回背景后仍可明确点击稳定地面确认站位：按真实身高、地面与投影渲染，不恢复默认比例。人工路径适当放宽相机距地面高度范围，站位必须由用户确认真实可站立地面。软件修改和测试代码已更新，未运行构建/测试，也没有验收“每次必成功”。没有可靠空间数据或景别不可执行时，不能保证真实测量成功。

## 数据和坐标

- `ArScaleSnapshot` 复制相机 view/projection、空间会话、配置和时间。projection 包含 VIEW 到相机 CPU 图像、裁切及旋转的变换，与选中照片对应。
- 地面只保存纯数值边界，采集最多每秒一次且仅几何变化时回传；不跨线程保留 Frame、Plane、Anchor。站位求解在后台执行，每 128 个候选检查取消。
- 在通过连续稳定性、面积及相机高度检查的水平平面中优先使用最低平面附近的候选，先解模型人物区域或人工建议位置的地面射线，再按 25 cm 网格寻找站位，距离 0.4～15 m，最多评估 16000 个候选。评分只考虑站位位置、背景遮挡和距离，不考虑固定人物占比。全身/环境景别确认头脚可见，半身/特写只要求头部可见，再按实际头脚投影裁切；半身/特写最终画面允许脚底在画面外。
- 裁切同时作用于卡片背景、卡片人像、找回背景的实时取景、视觉匹配与真实 JPEG 保存。轻点地面先还原到完整相机视图再命中测试。AR 保持原始 1× 镜头，方案裁切不等于硬件变焦；不会单独放大/缩小人像。景别裁切无法保留必要背景时只显示背景并提示站位计算失败，等待更多地面信息或调整机位。
- `ResolvedSpatialPlacement` 与最终解析结果记录固定身高、资源标尺版本、站位/朝向及参考相机。卡片使用参考相机，实时画面使用当前相机。手机移动后人像自然发生透视变化。
- 空间数据及身高均是 App 内字段，不加入 v1 网关序列化；缓存增加完整空间输入，回传同时检查请求、revision、相机配置与会话。
- 短暂跟踪丢失隐藏空间锚点，但保留屏幕人像参考和卡片；会话/配置失效后重新估算并重新对齐背景，不能复用旧世界坐标。

离线三构图同步修正：读取同一次预填充中六个合法摄影组合编号的 logits，按相对偏好排序后取前三，不再固定填入两个组合；四帧选景保持原样，不增加推理调用。该分数是模型对候选编号的相对偏好，不能当作独立的摄影质量评分。兼容旧单编号返回时，其他项仍明确标注为 App 备选。

## 资源标尺

`src/main/assets/avatar-scales.json` 绑定资源路径及资源版本。制作脚本：

```bash
python3 feature-camera-vlm/scripts/prepare_avatar_scales.py
```

脚本从参考动画首帧的实际蒙皮顶点测量：Rain 使用独立头部与鞋底，排除独立头发/附件；Rocketbox 使用不透明头部和身体，排除 opacity 附件。原 GLB 不修改，不用动作后的包围盒重新缩放。旧角色头部中与网格一体的发型不能自动细分，标尺边界仍需视觉验收；这里不宣称精确人体测量。新增资源或版本不匹配时只能显示近似卡片，不能显示未校准空间人像。

## 用户执行验证

以下命令本批未执行：

```bash
./gradlew :feature-camera-vlm:testDebugUnitTest
./gradlew :app:compileDebugKotlin :feature-camera-vlm:compileDebugAndroidTestKotlin
./gradlew :feature-camera-vlm:lintDebug
./gradlew :feature-camera-vlm:connectedDebugAndroidTest
```

真机检查：

1. 普通模式、AR 无地面/无深度时，三张卡片仍有人像并提示“估算比例”；环境深度或特征点会影响估算，可靠地面取得后升级实测，选中的卡片保持不变。
2. 在已知 2 m 门框旁、与门框相近深度放置 1.65 m 人像，检查头脚与比例。门框高度由实际已知尺寸提供，App 不假设所有门都是 2 m。
3. 检查桌面和低纹理环境：证据不足时应失败，不生成错误人像。靠近/远离，人像大小自然变化；在同一相机姿态下对照卡片与实时人像，脚底应落地。
4. 重点检查方案二，并切换全身、半身、特写；背景与人像应共同裁切，相近深度人物/门框的高度比例应保持合理。可站立范围或背景保留不足时应提示调整机位，不缩小身体。手动轻点地面后检查文字、脸部示范和站位。
5. 切换角色和身高，再生成；表情或动作改变不应改变身体真实尺度。普通相机行为保持。
6. 后台恢复、旋转、空间会话重建后，旧空间人像不应直接出现；重新确认背景和地面后恢复。
7. 校准期间重新扫描仍可取消；旧预览不能覆盖新扫描。
8. 找回背景到人像出现时取景不应突然缩放；实拍照片不含虚拟人像，背景取景应与显示画面一致。跟踪暂时丢失时只隐藏人像，不改变当前裁切。

日志标签 `VlmArScale`，本轮请提供从生成开始到失败/成功的这些日志：

- `尺度流程入口`：request、mode、source、tracking、stage、ready、session/config、地面数量、冻结照片是否有 AR 相机数据。
- `尺度计算输入`：方案、景别、身高、深度状态/点数、地面观察次数/相机高度、投影焦距项、保护区域数。
- `站位筛选汇总`：attempted、eligiblePlanes、depthPoints、solved、各拒绝类别的计数。包括不稳定/过小地面、相机高度限制、距离、地面范围、投影、前景遮挡、景别与背景裁切冲突。
- `未显示人像` / `比例校准` / `尺度求解完成`：结果原因或距离、光轴深度、投影占比、裁切和耗时。方法为 `TRACKED_PLANE`、`PLANE_WITH_DEPTH` 或 `CONFIRMED_FLOOR`。

入口及输入只在关键状态变化时记录；相同失败类别不重复输出整份候选汇总，深度采样不逐帧打印，不输出照片内容。深度状态包含 `UNSUPPORTED`、`NOT_YET_AVAILABLE`、`PAIR_MISMATCH`、`NO_CONFIDENT_PIXELS`、`RAW_NEW`、`RAW_REPROJECTED`。

ARCore 水平平面不能自动证明地面语义或可站立安全性，深度/平面质量与设备有关；水平桌面等误识别必须通过真机验收发现，必要时人工确认地面。姿势接触、美感、真实环境比例与实时效果以真机验收为准。

验收记录：设备/系统/AR 服务版本；角色/身高；参照物实际尺寸；模式/画幅；预览校准状态；距离与截图；脚底/透视/文字一致性；取消耗时；通过或失败及日志。

### 地面采集与恢复修正（2026-10-12）

- 平面缓存改用 ARCore 逻辑相等性，禁止按 Java 对象身份区分同一平面的不同包装对象。稳定证据按逻辑平面累积，最多记录三次；失跟重采，空间会话重建清空。显式启用水平平面检测。
- 缺少稳定平面时保持约 30 Hz AR 更新；分析期间被冻结图遮住的后台绘制独立限为约 10 Hz。构图已生成且仍缺少可靠地面时，主取景临时显示实时相机及识别地面引导，原选景照片、三方案、选择和模型结果不变；取得地面后自动校准并返回冻结构图展示，不重新调用模型。
- 先发跟踪状态、再发地面；稳定地面最多每两秒重发一次，同一尺度输入去重计算。跟踪恢复主动触发校准，旧会话/配置仍拒绝。
- 补充 `地面采集`（原始/跟踪/向上/边界拒绝/接收/稳定数量）、`地面回传`（接收与拒绝原因）、`跟踪受阻`（ARCore 原因）日志，按变化记录。
- 自测：地面先未识别时生成方案，按提示短暂向下并缓慢平移，再朝回目标背景；检查稳定观察次数达到三、自动出现校准人像、选择不丢失。遮挡后恢复跟踪、背景分析期间地面扩展、旋转后拒绝旧回调。缺纹理、桌面或地面不在视野仍可能不可测，不能保证每次成功。仅补测试代码和静态检查，未运行 Gradle/Android 测试或打包。

## 无地面估算接入（2026-10-12，当前显示规则）

`PhotoScaleEstimate` 记录来源、假定光轴距离、证据数与版本，进入最终规格和预览缓存，仍为 App 本地字段。空间站位标记 `estimated`，不通过 `hasMeasuredScale()` 冒充实测。AR 冻结帧额外复制最多 128 个高置信度空间特征点，释放 PointCloud 后使用数值快照；水平与垂直平面检测均开启。

预览统一经过估算和 GLB 渲染。无尺度元数据走屏幕参考；AR 相机和资源单位可用时可建立无 Plane 的估算世界锚点。背景确认后锚点未就绪或失跟时保留屏幕参考，恢复后切回空间人像。相机重绑定先恢复估算图，不等待地面。资源缺失仍真实报错，不制造替代动作。

日志“估算人像”记录来源、假定深度、证据数、投影占比和空间/屏幕路径。回归代码覆盖无地面/无 AR、深度/特征点改变比例、缺尺度元数据、升级实测、缓存/revision、屏幕参考与失跟。仅更新测试代码和静态检查，未运行 Gradle/Android 测试或 APK 构建；估算不保证真实比例与商业摄影质量。上述规则替代历史“未测量隐藏人像”的规则。
