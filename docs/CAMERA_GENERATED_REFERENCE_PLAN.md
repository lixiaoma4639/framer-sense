```text
                     有请求在途时不提交其他候选
```

Seedream 直接根据现场照片和文字要求创作，不再为每轮生图增加独立的 VLM 规划或复查调用。已有 VLM 选景结果可以复用，单张构图无需先调用 VLM；新链路不再受 GLB 的姿势、骨骼和表情枚举限制。

若结果不满意，用户可选择其他已生成图片，或主动换选中的一张／继续生成。APP 不因自动审美、可拍性或重复判断而隐藏成功图片、追加收费调用或反复重绘。生成质量通过开发阶段的固定素材集、人工验收和提示词版本迭代改善。

## 3. 此前讨论形成的产品结论

### 3.1 参考图与相机叠加使用不同资源

每个生成方案至少关联以下内容：

| 内容 | 用途 | 取得时机 |
|---|---|---|
| 原始现场照片与采集参数 | 背景对齐、来源追溯 | 冻结／扫描时 |
| 完整生成照片 | 单张构图预览、历史选择、详情、最终摄影效果参考 | 每次一个候选，生成并下载后展示 |
| 同尺寸人像透明 PNG＋画布位置 | 叠加在实时相机上供模仿 | 优先随该候选生成取得，不默认在点击应用后另调模型 |
| 完整图放大 | 按需看清动作与表情 | 详情本地缩放查看，不另建脸部图片资源 |
| 本次生成要求、差异提示与用户反馈 | 后续创作参考、避免反复请求相同方向 | 发起生成及用户操作时记录，不宣称等于图片实际动作 |

完整构图始终保留。透明人像不能替代完整参考图；PNG 扩展名也不等于文件一定具有有效透明通道。

当前图层模式的底图可能已去除人物，不能直接当成完整构图展示。每个候选在全部图层下载、合成及基础校验后进入可预览 `READY`。`GeneratedReferenceAssets.portraitPath` 为空表示仅有完整图，`hasPortrait`／`canApply` 独立控制人像应用；不伪造透明人像文件，也不因人物筛选失败丢弃完整构图。

生成照片中的表情直接作为示范，首版不再单独检测、裁切或生成脸部，也不设置独立脸部示范入口。用户需要查看细节时，在构图详情放大完整图片即可。旧 GLB 路线的脸部渲染功能保持独立。

### 3.2 环境允许适度变化，但动作必须能在现场完成

沿用用户已经认可的标准：主要背景结构、透视、时段和光线关系应接近现场；路人、散景等非关键细节不要求逐像素一致。

将保持人物身份、服装和配饰，以及避免新增座位、支撑物、道具、可站立平台、虚构光线、大幅换机位等要求写入通用提示词。这些是创作约束和开发验收标准，不表示 APP 已经自动验证实际输出满足全部要求。

首版建议固定输入视角、画幅比例和拍摄倍率，以人物动作、表情、站位及画面内安排提供变化。输入未拍到脚和地面时，不默认生成需要新地面条件的全身动作。更换镜头、显著改变机位与自动裁切映射后续单独扩展。

### 3.2.1 当前实际使用的通用提示词

2026-10-25 按用户最新七项要求整体重写：人像必须是核心；有主角沿用，无主角可创作真人、动漫感人物或原创人形角色；默认由 AI 自主选择艺术表达，不预设自然、克制等风格或固定动作方向。保留原现场、现实尺度、用户要求优先及 Seedream 原生多图层要求。APP 默认要求同步改为自主艺术创作，已有保存的用户输入不擅自覆盖。人物元数据线索补充少女、少年及动漫／卡通／人形角色，不新增像素识别或其他模型。

模板采用单张／多张参考的通用表述，但当前 API 仍按既有单图上传、每次一次请求，未增加多图上传或自动重试。创作序号只用于区分请求，不代表模型记忆历史，也不保证每次输出一定有艺术性或人物。实际入口为 `GeneratedReferencePrompt.build`，用户输入最多 2000 字符。

```text
请根据提供的参考照片，创作一张以人物为核心、具有鲜明艺术表现力的人像摄影参考构图，供用户在当前真实现场模仿拍摄。

一、人物与主角
无论提供一张还是多张参考照片，只要其中有明确的主角人像，就以该主角为创作主体，保持其身份特征、脸型、发型、体型、服装、颜色、花纹和配饰；除非用户明确要求改变，不擅自替换主角或外观，不把背景路人当作主角。
如果参考照片中没有主角人像，由你结合现场与用户要求创造人物，可以是真人形象、动漫感人物或原创人形角色。最终构图必须有人物，人物必须是叙事或视觉核心，不能用家具、建筑或其他环境物体代替主角。

二、艺术创作与摄影表现
以优秀摄影作品或影视画面的艺术完成度进行创作。综合设计景别、人物位置、姿势、身体线条、手势、头部朝向、视线、表情和情绪，利用现场已有的光影、色彩、空间层次、线条、留白与视觉节奏，形成有主次、有审美取舍、有情绪或故事表达的画面。
用户没有特殊说明时，由你自主选择适合现场的角色表现、构图和艺术风格，可以有摄影感、影视剧艺术性或其他艺术表达。不预设固定的动作、表情、情绪或风格，不套固定姿势模板，不能只做调色、美化或简单贴入人物。

三、现场环境与可拍性
以参考照片中的拍摄现场为依据，保持主要背景结构、物体位置、透视关系、天气、时段和光线方向，不重新设计、替换、拼接或扩展环境。保持原拍摄视角与画幅比例，允许在原图范围内适度裁切和调整人物位置。
人物只能使用现场可确认的地面、座位或支撑，不添加拍摄所需的新道具，不虚构地面、平台、座椅或支撑。支撑条件无法确认或原图没有拍到地面时，根据现场选择特写、半身或多半身，不强行补出全身与地面。动作与站位应能在现场模仿，肢体和手指结构合理，艺术表现不依赖改变环境、虚构光源、夸张透视或大幅后期处理。

四、人物与环境的现实比例
根据现场透视、空间深度和人物所在位置，参考周边处于相近深度的可辨识物体，综合判断人物合理的身高、体量与呈现大小，使人物和环境的比例符合现实，遵循近大远小及合理的遮挡、接触关系。
不把人物缩成微型，也不将人物不合理放大，不改变环境物体尺寸来迁就人物。缺少可靠参照时结合整体空间与透视保守安排，不编造精确尺寸，不以固定的人物画面占比替代现实尺度判断；动漫或原创人物同样遵守现场尺度关系。

五、用户要求与本轮创作
在现场环境、现实比例和图层输出约束下，优先满足用户明确提出的人物、风格、姿势、表情、情绪与景别要求；用户未说明的部分由你自主设计。本轮创作序号为 【本轮序号】，请独立构思本次画面，不因序号套用固定表现。

六、完整构图与原生图层
输出一张完整的人像摄影参考构图，并使用 Seedream 原生图层输出配套内容。底图保留现场背景，主要人物相关内容包含头发、服饰、飘带和原有手持物；人物作为完整透明图层输出时命名为 reference_person，若拆为多个相关图层，使用 reference_person_1、reference_person_2 等名称，并在描述中明确其属于主要人物及实际内容。
不把物体错误命名为人物。所有图层按返回坐标与层级叠加后应还原同一张完整构图；人物透明图层与完整构图中的位置、比例、姿势、表情和服饰一致，不另行重画或改变人物。画面不添加文字说明、箭头、边框或拼图。

用户要求：【用户已确认的输入内容；未提供时由 AI 自主创作】
```

缺少用户要求时传入明确的自主创作说明；已有用户要求仍优先。摄影效果、尺度和人物一致性属于提示词约束，不等于已验收的模型能力。

### 3.3 记录历史并引导变化，不增加自动去重循环

按「同一现场＋目标人物」记录已展示图片、对应生成要求和用户反馈。当前提示词仅附带本轮创作序号，由模型结合现场与用户要求自主设计；移除此前四组固定变化方向，不强制轮换自然站姿、手臂舒展或回望等模板。序号不等于历史记忆，不保证严格去重。

不额外调用 VLM 给生成图提取动作摘要。必须区分「要求模型生成的动作」和「最终实际生成的动作」，前者只能作为变化提示，不能作为严格去重证据。用户发现重复或不满意时，主动换图或补充要求，只重新生成指定候选。

新构图继续使用原始现场照片，避免仅基于上一张生成图持续编辑而积累漂移。当前图层模式只接收单张输入，首版不上传历史图，也不通过拼图绕过限制；仅保留要求与变化方向，持续生成不承诺严格不重复。定向换图仍使用同一现场原图和最新用户要求。

### 3.4 模型与首版范围

首版仅接入同一供应商的 Flash／Pro 两个可选模型；暂不接入 4.0 或其他图片供应商。现有 Qwen／Seed 视觉模型保留选景等原有用途，不强制加入新链路的创作规划与输出复查。

官方接口当前对 Pro／Flash 的普通生图按单图调用，当前每次只发一个独立任务，不预排第二个候选或使用组图方式。公开 API 的 `layer_decomposition` 将生图与拆分区分为不同模式；官网成对输出与该接口的具体对应方式列入第一步验证。若返回裁切图层，坐标以其输出底图画布为基准，需要统一成同尺寸透明画布。参见 [图片生成 API](https://docs.volcengine.com/docs/ark/image-generation-api?lang=zh&redirect=1) 和 [Seedream 5.0 Pro／Flash 教程](https://docs.volcengine.com/docs/ark/seedream-5-0-pro?lang=zh)。

生图配置建议如下，版本 ID 统一由配置管理，不写死在界面：

| 模型选项 | 接入安排 | API 配置基线 |
|---|---|---|
| Seedream 5.0 Flash | 默认，同期接入 | 当前公开 ID 为 `doubao-seedream-5-0-flash-260915` |
| Doubao-Seedream-5.0-pro | 同期接入，可选择 | 当前公开 ID 为 `doubao-seedream-5-0-pro-260628` |

首版服务于单人摄影：同一人物、同一服装、当前现场、固定视角的二维摄影参考。背景里可以有其他人，但必须明确目标人物。若选景帧没有可用的人物信息，要求补充目标人物参考，不能用现有「成年女性／男性 GLB」设置代替真人身份。

离线 MNN 能力继续服务原有视觉分析和 GLB 路线；生成式摄影参考明确依赖云端。「强制离线」固定使用 GLB，「指定云端」固定使用 AI 人像；自动模式由运行时路由决定，旧配置中的参考方式不再控制生成链路。不能在用户选择强制离线时悄悄上传照片，也不能把 GLB 备选称为同等的离线生图结果。

## 4. 与现有架构的衔接

### 4.1 共享拍摄流程，分开参考内容

建议增加统一的参考内容类型，区分 `LegacyGlb` 与 `GeneratedPortrait`，共享背景来源、方案唯一键、版本、方向、应用状态和拍摄流程。

生成式方案单独保存：原图来源、目标人物标识、批次、候选唯一 ID、任务状态、完整图资源、同尺寸透明人像资源、画布尺寸、归一化位置、完成顺序、生成要求、差异提示、用户反馈和实际模型版本。不要为了通过旧校验，给生成的人像强行填写一个不准确的 `PoseId` 或虚假的 `ResolvedPhotoSpec`。

旧 GLB 的渲染、校验和动作目录保留；生成式方案使用独立校验，直接读取图片资源，避免无关的大范围重构。批次与卡片选择可以复用概念，底层不继续要求每个方案都具有 GLB 动作列表。

当前扫描选景后会进入 GLB 导演流程；新增路线应在选景结束后直接进入图片生成，不先运行旧 `DirectorAgent` 生成 GLB 三方案，再额外生成照片。

### 4.2 统一画布，避免人像位置错位

完整图与可选透明人像按同一个候选管理。以 `z_index=0` 为底图，其余全部前景按 `z_index` 从小到大依次以 Alpha 混合合成。按[官方 API](https://docs.volcengine.com/docs/ark/image-generation-api?lang=en)优先用 `bounding_box.absolute`；其坐标属于未降采样的输出底图，解码缩小画布时按原始底图宽高同比换算。没有有效绝对坐标时使用 `normalized / 1000` 映射到画布。将图层缩放至边界框宽高，再放到对应左上角，不依赖图层位图的天然尺寸。底图与所有前景均参与完整图；人物筛选仅影响另行合成的透明人像。无可用人像、Alpha 或画幅匹配时仍保存完整图用于观察，禁用应用。合成继续串行执行。

本次新增 `SeedreamLayerCompositor`，详情显示实际图层总数（含底图）。使用 `LAYER_COMPOSITED` 逐层记录层级、坐标类型、目标矩形及是否选为人物，`COMPOSITE_ALL_LAYERS` 记录总数、前景数、人物层数、hasPortrait 和画幅匹配结果。补充绝对／归一化坐标、降采样、无人物仍可预览、16 个前景全部参与、真实 Canvas 遮挡顺序与透明叠加回归代码；仅编译模块及 JVM 测试源码，未运行自动化测试或真实模型请求。

### 4.3 现有操作需要按资源类型调整

| 操作 | GLB 路线 | 生成式路线建议 |
|---|---|---|
| 选择构图、继续生成 | 保持当前行为 | 展示完整照片，追加独立图片批次 |
| 更换动作／表情 | 本地枚举与渲染 | 用户描述后重新生成或编辑，提示真实等待状态 |
| 表情强度、角色外观、身体旋转 | 原功能 | 隐藏，避免误导为可即时调节真人照片 |
| 拖动／缩放人像 | 原功能 | 首版锁定，避免透明层与完整构图失配；后续再做一致的二维微调 |
| 脸部示范 | 单独渲染 | 取消独立入口与裁脸，构图详情支持整图放大 |
| 应用构图 | 校验并取得渲染预览 | 使用该候选已就绪的 PNG 进入背景对齐，不等待另一个候选，也不默认另调模型 |
| 对齐完成 | 放行参考显示 | 同样放行，但不表示真人姿势已经匹配 |

每次异步回传同时校验会话、背景、目标人物、批次、候选 ID、模型和 revision。另一个候选完成是当前批次的合法追加，不应被应用首个候选时的请求令牌变更误丢弃；旧会话或已被替换版本的回传不得覆盖当前参考。

### 4.4 云端任务与预算

建议扩展现有 `services/vlm-gateway`，增加图片任务适配和资源管理，商业版本的供应商密钥保存在服务端。开发验证阶段可以独立验证供应商接口，但不把现有聊天接口改造成图片接口。

生图调用需要独立任务 ID、幂等键、任务状态、受控并发和用户主动重试。网络超时后优先查询本方任务状态，不能直接重复创建收费任务，也不默认因结果不合审美而自动再生图。取消应停止后续步骤并隔离回传；已提交给供应商的任务不保证停止计费。

现有扫描预算是视觉请求次数／上传字节预算，不能原样覆盖生图。当前默认一轮一个候选任务，每个候选优先取得完整图和透明人像；实际图片／图层输出数量及调用次数分别记账，不能将「一张构图」直接当成只计一张输出图片。没有额外 VLM 规划／复查或自动质量补生成，已有扫描选景另计。图层费用不假设免费或只在用户选中后发生，按第一步真实账单验证。参见 [官方模型价格](https://docs.volcengine.com/docs/ark/model-pricing?lang=zh)。

服务端保存生成资源，客户端按需下载和解码，避免把历次高清图片全部放入 `VlmUiState` 的 Bitmap 集合。当前供应商图片链接有有效期，不能将临时链接当永久资源。

网关已持久化任务 ID、状态和原始图层资源；Android 已保存完整图、透明图及成功资源清单，并支持用户通过本地历史恢复成功候选和删除流程；不自动重放在途请求。后续恢复时必须重新确认现场，不恢复为「已经对齐」。接入用户上线前仍需完善照片上传用途、保存期限和删除流程，不在普通日志记录照片或密钥。

### 4.5 单候选请求与相机交互解耦

- 当前每次只创建一个候选与一个批次 ID，只调用一次 Seedream 原生图层接口；不预排第二张，不自动重试。
- 客户端生图并发上限为 1；任何候选在 QUEUED／RUNNING 时，继续生成、换一张、失败重试均不再提交。不是将原来的两个请求改为串行，而是本轮根本不创建第二个请求。
- 单个候选全部图层合成后即可选择和放大完整图；确认有可用透明人像后才允许应用、对齐和拍照。两类资源来自同一请求。
- 用户主动继续生成才新增一个候选，历史结果按完成顺序保留，不抢选中项、不改变已应用参考、背景确认或拍摄记录。
- 生成确认文案明确为一张；原离线 GLB 的三方案行为不变。
- 原双候选状态合并代码仍兼容历史数据，已有多候选成功结果不清理；但当前发起入口只创建单候选。
- 重新扫描、重启流程或用户明确取消时使对应批次失效。自动模式在无成功参考且当前候选因服务类错误失败后按原规则转离线；输入／图层拒绝不触发降级。
- 本次仅用于验证并发因素；现有 HTTP 400 尚未证实由并发引起。

| 环境场景 | 当前返回底图的 `description`；缺失时仅复用与该候选 frameId 对应的已有背景分析 subject／reason | 隐藏 |

图层内容说明不等于完整摄影分析，不据此臆测精确景别、曝光或动作参数；用户输入只用于生成，不能当作模型对成图的建议。三个字段都缺失时不显示空卡片或占位文案，放大仍可使用。新增字段随成功资源清单持久化，旧缓存没有说明时保持为空，不因补文案发起模型调用。当前修改不增加 VLM、生图或其他收费请求。

已补充说明来源与序列化、旧缓存兼容、背景 frameId 隔离、缺项隐藏、移除入口及白色按钮文字的回归代码；编译模块和 JVM 测试源码，未运行自动化测试或真实模型。真机效果由用户验收。

## 5. 分步开发与验收

以下步骤独立于历史扫描计划中的 P1～P6，避免混淆。建议按顺序推进，每步形成可评审结果。

### 第一步：真实接口与素材验收

内容：优先复现用户官网测试的「完整图＋同尺寸透明人像」；已按官方 API 接入图层模式，真实姿势创作效果与费用仍待核验。验证 Flash／Pro 的单候选、单次请求流程，至少覆盖汉服、发丝／飘带／薄纱、半身、夜景、多人背景。

产出：完整图／同尺寸 PNG 素材对、官网体验与 API 对应记录、模型能力表，以及首个可预览、首个可应用、单候选完成的耗时和完整费用记录。

通过条件：目标人物正确、动作表情一致，透明画布和完整图对应，明确一次候选需要哪些真实调用与费用。若 API 不能直接成对返回，必须单列差异和可选实现，不将官网一次操作推断为单次 API；其他数据结构、UI 和状态开发不必因此停止。

### 第二步：接入参考资源类型，先打通相机叠加

内容：新增生成式参考数据及资源读取链路，使用第一步真实素材完成「完整图卡片 → 选择 → 应用 → 原图对齐 → PNG 叠加 → 拍摄」。测试素材仅用于开发验证，生产不得伪装为实时生成结果。

复用：`VlmContract`、`VlmCameraViewModel`、构图批次、`CameraPhotoViewport`、`BackgroundReference`、`LiveReferenceAvatar` 和拍照保存链路。抽出背景对齐所需的来源／裁切描述，避免其必须依赖 GLB 人偶数据。

通过条件：横竖方向及支持的取景比例下，人物位置和尺度一致；切换方案不串图；对齐前后显示门控正确；真实照片不包含参考层；旧 GLB 路线不回归。

### 第三步：多模型配置、直接生图与资源包接入

内容：新增「通用要求＋用户要求＋候选差异提示」组装器、独立 Seedream 适配、服务端任务及资源包。Flash 默认／Pro 可选，保存模型选择，不添加 4.0。使用较清晰的现场原图，不使用长边 768 像素的 VLM 缩略图作为唯一输入。扫描选景后直接进入图片链路，单张构图不先调用 VLM。

交互：默认提交两个具有不同创作侧重的独立候选，在限流允许范围内并发。逐张发布完整图及人像资源的就绪事件，不等待整批结束。部分失败不回滚成功结果，失败项由用户主动重试。

通过条件：两个模型均能独立选择与正确路由，配置和结果可追溯；候选具备可预览／可应用状态；单张与扫描两种来源均可接入。未生成的备选背景仍按需调用，旧批次保留，不因切换模型自动付费重绘。

### 第四步：首个可用即前进，后台结果安全追加

内容：把现有整批生成／全局忙碌／应用时取消工作的逻辑，拆成候选生成状态与当前应用、背景对齐、拍照状态。完整图和同尺寸 PNG 下载并做程序校验后直接复用，不在点击应用时默认提交新的图层请求。

交互：当前每次一个候选，全部图层合成后展示完整图供选择与放大；存在可用人像才放行原图对齐和拍摄。无人像时明确提示并禁用应用，不将去人物底图或完整场景图冒充透明人像。用户主动继续生成才新增下一张。

通过条件：两个任务任意顺序成功或失败均正确；首个成功后立即可用；应用第一张不取消第二张；第二张追加不清对齐和拍摄进度。验证旧会话迟到结果、PNG 先后下载、重新扫描、单候选重试及方向映射；当前参考不串版本。

### 第五步：历史记录、差异引导与用户主动换图

内容：保存生成图及对应要求、差异提示和用户反馈，下一轮调整创作侧重；不新增 VLM 识图、审美评分或自动重绘。图片解码、画幅、版本和重复文件等确定性问题由程序处理；文件内容相同可标记，但不据此自动发起新收费任务。

历史以「会话／现场＋目标人物＋方案版本」管理。用户可以选择其他已有图片，或主动换选中的一张；继续生成追加一个候选的新批次。默认沿用原始用户表达并追加新的差异提示，不要求用户重新编写整段提示词。完整资源按容量清理，不默认将全量历史上传给模型。

定向修改只编辑选中方案；成功后创建新的完整图与配套 PNG 版本，用户再次应用时使用该版本资源包。准备期间保留旧版本，失败不覆盖已可用资源；不能将新完整图与旧透明层混用。不自动循环调整提示词和生成。

通过条件：每轮的请求数量符合用户操作；换一张仅生成指定候选；成功图片即刻可选；历史可回看且创作方向持续变化。实际动作差异率在固定测试集中统计，不宣称提示词历史等于严格动作去重。

### 第六步：上线稳定性与真实摄影验收

内容：补齐任务恢复、网络中断、限流、超时、重复点击、资源过期、缓存清理、成本统计与上传／删除说明；集中回归方向、变焦、前后台、人物移动和多人背景下的原图对齐。沿用现有手动确认入口，不把背景确认解释成真人动作达标。

建议用固定现场集记录：可用构图比例、人物与服装保持情况、成对 PNG 就绪率、明显重复率，以及首个可预览／首个可应用／整批完成的 P50、P90 和实际调用、图片、图层总成本。特别测试用户主动继续生成期间已有参考、对齐和拍摄状态的保留。具体发布阈值在第一步取得数据后确定，不预先承诺尚未测量的秒数和质量。

视觉质量主要在发布前通过人工评审、模型选择、提示词版本和适用场景范围改进；若可用率不足，应调整产品方案，不以线上自动重绘循环掩盖问题。用户使用时不经过自动审美复查，也不以「已经验收人物动作」等文案作保证。

通过条件：用户在实际现场完成「选图、对齐、模仿、拍摄」，能拍出姿势与表达接近参考的真实照片；问题可定位、失败可恢复，重试不会无控制地产生成本。

自动化验证重点为资源协议、坐标映射、状态门控、版本隔离、任务幂等和预算；按仓库约定补充测试代码，Gradle／Android 自动化测试由用户本地执行。视觉质量和现场效果单独真机验收。

### 后续增强：真人实时动作指导

在上述闭环稳定后，再评估人体／面部关键点，从生成参考图提取目标姿态，对比实时人物，提示少量明确动作，例如抬高手臂、转头或调整人物大小。优先做大关节与头部方向；表情沿用完整参考图和整图放大，不恢复独立脸部示范为前置步骤。

这属于新增能力，不能把当前背景 ORB 对齐直接复用为人体动作判断。首版不以精确手指、情绪审美打分或任意三维视角指导为上线前置条件。
