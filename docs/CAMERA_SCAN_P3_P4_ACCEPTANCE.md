# P3＋P4 软件交付与真机自测

2026-10-02。软件接入完成；本批不生成 APK、不运行仪器测试、不调用真实收费供应商。P5 真人实时纠偏、P6 成片评估尚未实现，五个专业动作样片继续待素材验收。

## 本次流程

开始扫描 → 结束扫描 → 多图选景前三名 → 第一名三种构图（切换其他背景时按需生成并保留）→ 应用任一方案 → 找回对应背景 → 人像参考和指导 → 手动拍摄。

实时页提供“开始扫描”和兼容的“单张构图”。扫描中保留取景，只能结束、取消或标记偏爱；构图、拍照、倍率及模型管理被门控。结束后关闭新增入口，排空单个队列槽中的已接收任务，然后固定输入。空输入不调用模型。达到 90 秒或 32 MiB 时提示手动结束，不自动分析。

采集最多每秒 4 帧，32 张、3 个偏爱；重复背景经局部特征和视角一致性验证后才合并，质量改善可替换。容量满后结合视角或时间间隔与质量替换非偏爱帧，保留多样性。无纹理画面不因低锐度单独判为模糊。相机分析与预览、拍照共享 ViewPort，KEEP_ONLY_LATEST；复制 YUV 后关闭 ImageProxy，单工作者、有界队列。

旋转向量跟踪相机 -Z 光轴，传感器频率累计转动再关联图片采样，支持跨界、多圈、反向和俯仰。累计转动量不是有效覆盖率。只有 Camera2 声明 REALTIME 且姿态样本足够接近时才关联传感器；未知时间源使用扫描专用分析用例和视觉帧，停用方向箭头。旋转重绑建立新的相机配置版本，原会话保留；后台/相机中断停止采集，保留有效帧，恢复后明确继续分析或重新扫描。

选景最多上传 8 张代表帧、3 MiB JPEG，优先偏爱与视角多样性，界面显示实际比较数量。默认直接冻结第一名并生成三方案，不要求用户先挑帧；构图面板仅用一行横向列表，按背景名次混排已生成构图与未生成背景的缩略卡片；点击未生成背景先选中并展示该原图、隐藏详情，确认才生成；取消或关闭保留所选原图，仍可选回已有构图。已生成的构图和人物调整按背景保留，所有方案放入横向列表，按背景及生成批次保留；切回已生成背景不重复调用模型。手动备用入口仍可展开扫描缓存帧，但本次最多保留三个背景，不淘汰旧方案。帧来源仅在 App 内保存，贯穿最终事实、预览、指导和应用校验；v1 序列化不变。背景保留区域进入提示词并做裁剪保留校验；地面安全、真人光照等未知信息不伪造。

每次扫描的云端请求共享 8 次调用、24 MiB 上传预算，覆盖最多 2 次选景与三个背景各最多 2 轮构图；云端选景累计最多 2 次（含纠正和切换）。云端重新分析、重新生成、导演修改与供应商切换不会重置；手动动作/表情不调用模型。云端耗尽保留已有方案，可切换离线继续分析、拍照或重新扫描。离线选景与构图不读取或消耗云端预算，不设扫描会话累计调用次数限制。

## 网关准备

先按 [网关部署说明](../services/vlm-gateway/README.md) 升级并重启服务。多图能力默认关闭，必须对实际模型进行验收，并让 `*_MULTI_IMAGE_MODEL` 与 `*_MODEL` 完全一致，再设置 `*_MULTI_IMAGE_MAX_IMAGES=1..8`。仅填密钥不会开启多图。

强制离线使用本地多图选景，最多比较 4 张代表帧，自动冻结最佳帧并继续单图三构图；不查询网关、不上传图片。需要已有可加载的 Qwen3-VL-2B MNN 模型，缺模型或推理失败明确提示并保留扫描集。旧网关、未声明多图及云端暂不可用时，提示具体原因，优先提供继续自动选景和检查模型设置；关键帧默认折叠，仅点击“手动选择背景（备用）”才展开，选背景后走原单图流程。

## 背景确认

OpenCV 4.12.0 在端侧工作，不上传实时帧、不调用 VLM。可靠姿态只给粗略左右/上下方向；参考叠图始终允许手动对齐。ORB 长边 640、最多 800 特征，5 Hz，Hamming 比值筛选及 RANSAC。

集中门限位于 `scan/ScanPolicy.kt`：标准可靠证据为至少 30 匹配、15 内点、50% 内点比例、20% 特征范围与至少 3 个象限，且几何有效。实时找回背景另允许强局部证据：至少 45 匹配、30 内点、65% 内点比例、15% 特征范围及 2 个象限，容许裁剪／实际遮挡后可靠匹配的分布不足。扫描去重继续使用标准证据与 `aligned` 的 3%／3°／8% 标准，不扩大视角合并范围。

实时自动对齐使用 `alignedForGuidance`，允许角点偏差不超过像素对角线 6%、旋转不超过 6°、比例误差不超过 15%。至少 3 帧合格结果，跨度达到 500 ms 才确认，合格帧间隔不得超过 500 ms。候选期间可跨过一帧仍有可靠证据、且几何偏差不超过 8%／8°／18% 的边界波动；该帧不计入合格帧数、不触发确认。连续边界帧、无匹配、明显偏离、超时或参考变化重置计时，日志新增 `briefGaps` 和证据类型。匹配使用原始背景照片与原始相机帧，不按虚拟人像区域排除特征。弱纹理、遮挡、重复建筑及视差请手动确认；自动与人工确认分别记录。改倍率、重绑/旋转、后台及明显转动清除或重新确认状态，传感器基准变化停用旧方向。确认背景后展示人偶，顶部仅留简洁拍摄提示，详细人物指导保留在构图详情，仍允许手动拍照；没有检测或验收真人姿势。已补用户失败指标回放、强局部证据、单帧边界波动／连续失效／长采样间隔回归代码，未运行，需真机验证易用性与误匹配情况。

缓存按控制器与会话隔离，仅保留 JPEG、小特征与按需缩略图。取消/重扫等待旧读取任务退出再删；销毁后异步清理所属目录，下一扫描清理进程遗留目录。进程重建提示重新扫描，不恢复任务。

方案间参考特征修复：虚拟人像是后期覆盖层，不属于参考照片与实时分析帧。此前按人物大小排除背景，既可使参考点清零，限制排除面积后仍会丢掉有价值纹理；现已取消该策略，所有方案按同一原始背景流程提取特征，保留现有 RANSAC 与空间／时间校验。参考缓存不再包含人物布局，仍按方案 ID／版本、裁剪、相机配置与参考 epoch 隔离。重建日志增加 `featureSource=RAW_BACKGROUND avatarMask=NONE excludedArea=0`。回归覆盖有效纹理全部位于旧人物排除区域、仅改虚拟人像大小／站位时对齐状态保留、原始 NV21 → ORB → 自动确认及参考重建清计时，均未运行。

## 2026-10-03 离线多图接入

云端最多 8 张/3 MiB 的流程保持不变。强制离线自动精简最多 4 张，优先保留偏爱和不同视角；每张 JPEG 独立进入 MNN Omni 的视觉编码通道，不拼图、不逐帧调用，也不使用画面质量规则替模型选择。4 张是当前应用限制（2026-10-06 从八张恢复），并非 Qwen3-VL 的固定模型上限。该模型没有可跨设备承诺的统一最大帧数，实际受视觉 token、上下文、内存和耗时影响。

`OfflineScanViewAgent` 当前读取一个数字编号，编号必须唯一且绑定本次提交顺序，范围 1..实际提交数；0、不存在的编号及重复选择均拒绝，不猜测来源或编造区域。兼容旧 `SELECT=编号` 及 `SUBJECT/REASON` 说明字段，缺失说明保持未知。提示词明确这是人物稍后入镜的空景背景比较，无人不应成为拒绝理由。默认 JNI 一次视觉预填充后，在真实模型最后位置的合法数字分数中选出最高项，不自由生成 SELECT 格式文本。界面以真实帧序号及“未提供选景说明”展示，不因缺少说明丢弃有效编号。每次选景最多一次推理，失败不自动额外纠正；用户可重复重试，不设扫描会话累计调用次数限制。离线接口不接收云端预算，本地单图推理也不扣减预算，包括自动路由落到本地的构图。选景后原离线构图子任务保持一次调用，提示词同样明确无人时给出未来站位及姿势建议，正常完整流程合计两次推理，上传字节为零。单次最多四图、串行执行、取消和停滞保护继续保留，自动/云端模式的多图降级路由不变。

输入复制为长边最多 448 的私有 JPEG，副本保持到原生推理退出才删除；取消只丢弃迟到结果，不提前删正在读取的图或释放句柄。缩小 JPEG 是降低输入开销的措施，不承诺固定视觉 token 数。未确认地面安全、真人光照和区域坐标保持未知。真机需记录 1、2、4 张输入的耗时、峰值内存、发热、选景准确性，以及取消后重试的表现；本轮不运行真实权重推理。

## 离线八帧与摄影选景标准（历史：2026-10-06 已恢复四帧）

离线比较上限从四张提高到八张，Kotlin、JNI 和原生媒体前缀统一接入。缓存不足八张时全部比较；超过八张时保留偏爱和方向/时间多样性，从本次扫描最多三十二张中选出八张代表帧。代表帧按采集时间排序后交给模型，图片编号绑定这个实际顺序，避免清晰度最高的候选固定占第一个编号。云端筛选和上限不变；离线一次选景调用、无累计预算限制、无需人工挑帧。

选景提示词依次考察：人物全身/半身空间与轮廓分离、环境主体保留与杂物/亮点干扰、前中后景和引导线及视觉重心、可见曝光色彩和清晰度。偏爱只在摄影条件相近时优先；禁止仅按序号或单独清晰度作决定。不把画面中的空间当成安全可站立区域，不推测真人面部光照。仍仅输出唯一 `SELECT=1..实际提交数`，不增加多轮打分或自动重试。

日志增加 `rubric=PORTRAIT_BACKGROUND_V2`、`compared=8`（缓存足够时）、提交编号与帧 ID；进度显示实际比较数。App、JNI、JVM/设备测试代码和宿主 C++ 测试代码编译通过，测试未执行，不生成 APK。回归代码覆盖第八帧可选、第九帧拒绝、偏爱和方向保留、排序来源对应与八张独立 JPEG 输入。真机建议对同一场景记录八帧选景结果、人物实际站入后的背景干扰、耗时及峰值内存；帧数增加和提示词不能保证小模型选出客观最优背景，摄影效果仍需人工验收。

## 2026-10-06：恢复四帧与受限编号选择

根据真机八帧约 246 秒且输出 `SELECT(SELECTING)` 的记录，离线上限恢复四帧，云端保持八帧。保留摄影标准、偏爱和方向多样性及时间顺序，缩短选景提示词；要求一个具体数字，取消带变量占位的格式指令，不自动再跑一轮昂贵的视觉推理。

`MnnNative.inferImages` 仅用于选景：从实际模型 tokenizer 校验 1..N 为独立、可逆的非结束 token，然后通过 MNN 公共 `response(..., 0)` 完成视觉编码和预填充，读取 `getOutputs()` 的真实下一词分数，只在这些合法编号中取最高分。可识别单行或完整未填充序列的最后一行；异常分数、错误编号映射或分块/填充位置不明确均报错，保留原扫描图，不兜底选首帧。不更改模型原采样配置，不手动从 `current_token=-1` 继续解码，后续单图构图仍走原文本推理。

新日志应包含 `compared=4`（帧数足够时）、`protocol=BACKGROUND_DIGIT_CONSTRAINED`、`method=constrained_logits`、合法编号的分数和 `selected`，返回 raw 是一个数字。`generatedTokens=0` 表示选景采用分数选择而未自由生成文字，不能将编号分数当成摄影质量百分比。真实模型结构兼容性、选景质量和总耗时仍由真机验收。

更新 JVM 回归：四帧来源、数字与旧 SELECT 协议、`SELECT(SELECTING)`/0/5/歧义结果拒绝。原生测试代码覆盖合法编号分数排序、非编号高分排除、空/重复/越界 token、NaN/无穷分数及输出位置校验；设备测试代码恢复四张独立 JPEG。主 App、JNI 和测试代码仅编译，不执行测试、不生成 APK。

## 2026-10-20 前三背景与按需构图

本节更新上述历史单背景约定。离线 JNI 同一次视觉预填充，将合法编号分数排序取前三，返回如 `3,1,2`；不足三张按实际数量，不额外比较两遍。分数是模型编号偏好，不是审美评分。云端同一次请求要求 primary＋最多两项 alternatives，均须绑定真实提交帧。旧单编号结果继续兼容，不凭清晰度补造推荐。

首次只生成第一名的三方案；点击其他背景先选中并展示对应原图、隐藏构图详情，再弹出“继续生成构图”确认框。确认才生成；取消／关闭不调用模型，保持该背景选中和原图预览；选择已生成构图可恢复其合成图；详情默认收起，由独立“构图详情”按钮控制，卡片和“应用构图”不随详情收起而隐藏。各组以背景 ID 缓存原图、拍摄方向、来源绑定、三方案、预览和人物调整。仅保留一行横向列表，按背景名次混排已生成方案与未生成背景缩略卡片，不另设背景列表。生成后在背景原位置展开三方案；先生成背景 3 时，仍排在背景 2 占位卡之后。不同背景都有 p1/p2/p3 也不会覆盖。同背景“继续生成”成功后追加三方案，不替换旧结果；显示编号依次为 1-1…1-3、1-4…1-6。从旧批次发起也追加至该背景末尾；失败、取消或迟到结果不占编号。内部各批仍独立保留 p1/p2/p3 及三方案校验，选择／修改／应用依背景、批次和方案定位；拍摄完成状态也隔离批次。新一轮扫描、取消本次扫描、重新冻结单图或导入新图才清空本次缓存。
