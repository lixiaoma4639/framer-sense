# 扫描摄影 Agent 开发执行计划

更新日期：2026-10-02。

状态：P1 代码与回归测试已完成；P2 软件接入完成，累计 73 项 JVM 测试通过，主 App 与设备测试代码编译通过，模块 Lint 0 错误、16 项非阻断警告。本批未生成 APK；真机 GPU、动作自然度和表情可读性待用户验收。五个专业样片仍待素材验收，P3–P6 尚未实施。设计依据见 [扫描与人像 Agent 方案](CAMERA_SCAN_AGENT_PLAN.md)。

## 1. 已确定范围

- 朋友帮拍：一人持机，一人入镜；首版以单人环境人像为主。
- 用户点击“开始扫描”才记录本次场景；按钮变为“结束扫描”；点击结束后固定输入，再启动 Agent。
- 支持局部、接近一圈、多圈和来回扫描，不要求扫满 360°。
- 沿用云端＋离线路由，优先完成云端体验；离线能力明确降级。
- 文字、人偶与实时验收共享最终动作；专业摄影动作库支持经过审核的姿势与表情。
- 继续采用拍照 MVI，业务先放在 `feature-camera-vlm` 内。
- 自动化测试随各批次编写；用户本轮已授权运行构建和代码验证，实际功能与视觉体验由用户在真机执行。

首版完整交付是“扫描、选景、找回背景、人物指导、拍摄、成片检查”。三维空间锚定、精确米数站位和任意生成动作作为后续增强。

### 任务

- [ ] 定义 `StartScan/StopScan/CancelScan`，以及扫描中、整理中、输入就绪的状态；记录 `scanId` 和起止时间。
- [ ] 绑定同一 ViewPort 的连续分析；复制必要数据后释放相机帧，丢弃过时帧，避免阻塞预览。
- [ ] 建立相机光轴方向、屏幕旋转、俯仰与图像时间戳的关联；缺少姿态能力时降级为视觉关键帧。
- [ ] 结合姿态、视觉变化与质量去重，支持跨界、多圈、反向及上下扫；保留方向多样性。
- [ ] 缓存设置帧数、字节数和时长上限；到达硬预算提示结束，不自动启动 Agent。
- [ ] 点击结束后，过滤时间窗口外或错误会话的回调，固定不可变扫描输入；无可用帧则提示重新扫描。

## 6. P4：多图选景、生成方案与找回背景

### 改动范围

扩展 `model/`、`data/VisionModelProvider.kt`、`agent/` 和 UI；网关改动限于 `services/vlm-gateway/gateway/models.py`、`providers.py`、`app.py` 及对应测试。

### 任务

- [ ] 增加 v2 任务协议和实际供应商能力声明；保留 v1 单图兼容入口。
- [ ] 多图请求有帧 ID、来源元数据及图片数量/字节预算；响应不能引用未发送的帧或跨帧使用坐标。
- [ ] 比较代表帧，返回一个主视角及最多两个备选；用户喜欢的背景进入选景偏好。
- [ ] 在主视角内生成构图，结合实际角色动作能力得到最终方案，复用现有几何与投影校验。
- [ ] 会话控制器统一管理选景、生成、修正和供应商切换预算；取消与拒绝规则延续现有行为。
- [ ] 姿态用于粗方向提示，视觉背景匹配确认画面；识别不可靠时提供参考图手动对齐。
- [ ] 镜头/倍率/横竖屏/明显换机位后重新确认取景；不从方向角推断返回原机位的空间路线。
- [ ] 离线或多图能力不足时保留扫描集，由用户选择背景，再使用现有单图离线能力；清楚标明未做完整跨视角比较。

完成条件：推荐有真实帧依据；能带持机者找回目标画面；不伪造未观察内容；超预算和网络故障可结束或降级。编写协议、路由、有限预算、背景匹配及过期结果测试；网关测试使用模拟上游。

- [ ] 多人时点选目标；目标丢失后不自动改选路人；观测不可靠时暂停对应姿势验收。
- [ ] 按取景、人物位置、比例、背景遮挡和支持姿势依次纠偏，区分持机者/入镜者及画面左右/人体左右。
- [ ] 加入稳定门控、滞回、提示冷却与失败回退，保持一次一条指令。
- [ ] 人偶、轮廓和观察目标均使用 `ResolvedPhotoSpec`；半身、特写的裁切条件独立处理。
- [ ] 将审核后的动作库逐步扩展到约 30–50 个基础姿势，并逐角色审核。

完成条件：真实两人能依照指导完成布局；动作可模仿、提示不会反复冲突；不能自动检测的动作由示范/人工确认处理。编写目标丢失、多人、镜像、稳定门控和景别验收测试。

## 9. 第一批的具体交付包

首个代码批次仅执行 P1，并提供：

1. 四个当前角色的表情通道映射及能力验证。
2. 从最终方案派生的结构化操作指导，覆盖备选、去重、拖动与缩放。
3. 渲染实际采用结果与 UI 状态同步，包含明确降级信息。
4. 针对真实资产和原问题的自动化测试代码；真机验收步骤交由用户执行。
5. 同步最贴近变更的功能文档；核心行为/数据流变化时更新 `PROJECT_CONTEXT.md`。

P1 不依赖采购或制作新角色即可开始。后续素材决策安排在 P2 素材任务之前，当前不为未确认的外观、预算和供应商做不可逆选择。
